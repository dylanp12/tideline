    EU AI Act  ·  Articles 12 & 14

    Records cannot be backfilled.

    Annex III high-risk obligations — record-keeping and human oversight — apply from 2 December 2027, with breaches reaching €15M or 3% of worldwide turnover. The deadline is not the hard part. The hard part is that a decision your agent makes today is provable in 2027 only if it was recorded today.

    Observability tools are trace viewers for developers debugging, not evidence for someone who does not trust you. Governance platforms sit at the policy layer and never see what the agent actually did. Platform-native tracing is single-vendor by design. Tideline is the one that is vendor-neutral, in the execution path, and independently verifiable.

    Integrity

    Alteration is detectable

    Each event commits to the one before it. Change a field and verification fails, naming the event — as it does above.

    Article 14

    Oversight lives in the record

    An approval gate is two events in the chain, not a table beside it, so the oversight trail cannot drift out of step with the record.

    GDPR Art 17

    Erasure keeps the evidence

    The chain commits to each field by digest. Erase a value and the digest stays, so the record still verifies. Retention and erasure stop being mutually exclusive.

    npm  ·  PyPI  ·  crates.io  ·  Go

    Record a run, gate the risky part, verify the result.

    The same shape in every language, so examples translate line for line. The call that matters is gate: it does not return until a person decides, and by then the request and the decision are both on the record. 

    // npm install @tideline/sdk
const run = await tl.startRun({
  runId: "loan-4821",
  agent: { name: "underwriter", version: "2.1.0" },
});

await run.record({ kind: "tool_call", name: "pull_credit_report" });

// Waits for a person. Both halves are on the record by now.
const decision = await run.gate({ action: "Approve EUR40,000 loan" });
if (decision.approved) await run.complete();

const { chain } = await run.verifiedEvents();

    To check a record without a server in the picture: cargo install tideline-cli --no-default-features builds a binary that cannot open a socket, which is what you want when the thing being audited is the server you would otherwise be talking to.

    Conformance

    Four implementations, held to the same bytes.

    The protocol is specified separately from this implementation, and every SDK is tested against one frozen corpus and one HTTP transcript. A change that one language gets wrong fails the build rather than someone's production record.
